# 部署说明

这是参考部署方式，目标是说明项目由哪些部分组成、各部分按什么顺序启用。请根据自己的服务器、域名和网络环境调整。

## 1. 准备环境

- 一台长期在线的 Linux 服务器；
- Docker 与 Discourse 官方容器环境；
- 可选的正式域名；
- 可选的 Cloudflare Tunnel；
- 可选的本地模型服务，用于内容审核和公聊助手；
- Android Studio，仅在需要重新打包安卓应用时使用。

## 2. 放置插件

将 `plugin/innox-lan` 放到 Discourse 容器内：

```text
/var/www/discourse/plugins/innox-lan
```

`server/app.yml` 中已经给出挂载示例。正式域名、管理员联系邮箱和实际目录需要自行替换。

## 3. 首次初始化

插件加载后，在 Discourse 容器中执行：

```bash
cd /var/www/discourse
RAILS_ENV=production bundle exec rails runner /shared/innox-lan/../harden_community.rb
```

如果脚本通过挂载目录执行，请把命令中的路径改成你服务器上的实际位置。

初始化会设置社区名称、登录要求、会话时间、密码规则、新成员审核、成员资料字段、论坛标志和基础词表。

## 4. 启用匿名社区

把 `server/enable_anonymous_community.rb` 放进容器可访问的位置后执行一次。它会：

- 创建“匿名社区”板块；
- 允许已登记成员切换匿名身份；
- 把匿名板块编号写回插件设置；
- 让安全内容直接发布、风险内容退回；
- 在审核服务不可用时转入管理员待审；
- 开放论坛私聊与即时聊天。

验证脚本 `server/verify_anonymous_community.rb` 会使用临时数据并回滚，不会保留测试账号和消息。

## 5. 启用公聊助手

先确认本地聊天模型已经运行，再执行 `server/enable_ai_chat.rb`。脚本会创建一个标明为非人类的“科仔 AI 助手”账号，并关闭它的私聊权限。

助手只处理公开聊天频道中的点名消息。输入和输出都会经过独立的安全检查。

## 6. 配置公网入口

从 `server/cloudflared-config.example.yml` 复制一份本地配置，填写自己的通道编号、凭证文件和域名。

真实配置 `server/cloudflared-config.yml` 已被排除在 Git 上传范围之外。不要使用示例值直接上线。

启用后依次检查：

1. 内网论坛是否正常；
2. 公网首页是否正常；
3. 公网登记页是否能打开；
4. 公网和内网是否能读取同一篇帖子；
5. 安卓安装包是否能从公网完整下载。

## 7. 安卓应用

在打包前修改：

- 公网地址；
- 内网备用地址；
- 应用名称；
- 图标和版本号。

然后执行：

```powershell
cd android
.\gradlew.bat assembleRelease
```

安装包生成后，应在实体安卓手机上测试登录、头像选择、网页跳转和公网失败后的内网切换。

## 8. 上线前检查

- 删除测试账号、测试消息和测试待审内容；
- 确认管理员密码没有写入源码或说明文档；
- 确认隧道凭证、证书私钥和环境变量没有进入版本记录；
- 确认新成员实名登记页、登录页和普通注册入口符合预期；
- 确认审核服务不可用时不会直接放行风险内容；
- 做一次独立备份，并实际恢复到一个隔离环境；
- 为内网配置正式证书，避免长期使用普通未加密连接。

## 9. 已知限制

- 实名信息由用户自行填写，不是证件核验；
- 轻量模型只能做第一道风险筛查；
- 公网通道依赖服务器所在网络的外连能力；
- 当前公开版本没有附带完整备份编排；
- 若不替换示例域名和内网地址，安卓应用不会自动适配你的环境。
